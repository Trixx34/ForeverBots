# Rules v4 (2026-10-12)

Rules derived from `run-1000bot-30m-analysis-20261012.md`. Every rule has a switch and defaults to ON. Settings are in `src/server/worldserver/botserver.conf.dist` and loaded in `BotRules.cpp`. Like the other `Bot.Rules.*` rules they honor `Bot.Rules.ArmPct` (A/B arms) where noted by `BotRules::Applies`.

| Rule | What it does | Options (default) |
|---|---|---|

## quest_blocked volume: skip early reasons, per-level summary

Logging only; bot behavior and the internal blocked state are unchanged.

- `Bot.Log.QuestBlockedSkipEarly` (default 1): rows with reason `QUEST_LEVEL` and `QUEST_PREREQ` are not written (they were about 75% of the rows). They are counted per bot after the R-V4-03 limits, so the count equals the rows that would have been written. All other reasons are logged as before. 0 = old behavior.
- `Bot.Log.QuestBlockedSummary` (default 1): when the bot's level differs from the level at which the skipped rows were counted, one `quest_blocked` row is written: reason `QUEST_BLOCKED_SUMMARY`, severity info, no quest id, details `{"QUEST_LEVEL":n,"QUEST_PREREQ":m,"level":L}` (L = the level the counts belong to). It is written directly and does not pass through the skip filter. The counters reset after each summary; the bot's last partial level is not summarized until it levels up.

## Start gear switch

`Bot.StartGear.Enabled` (default 1) already existed. With 0, `BotAI::RunStartGear` returns before `BotStartGear::Grant`, and `Grant` itself also returns when disabled, so no `START_GEAR` or `START_GEAR_NONE` row is written and no item is granted (both the LOGIN and the LEVEL pass). Use it for the gear A/B test; items already granted stay on the characters.

## Notes

Configs are read once (hot reload applies through the existing reload mechanism). Rule 1 only runs the neighbor scan for casters of level 4 or lower, so the per-tick cost for other bots is zero.

## Stuck test counts path movement

`Bot.AI.Move.StuckMoveYards` (default 6, 0 = old behavior): in `BotMotion::Update`, a moving, non-rooted bot that has walked more than this many yards from the last check point resets the NO_PROGRESS timer (`_bestMs`) without lowering `_bestDist`, so ramp and switchback detours are no longer flagged. The `_everMoved` guard and the `StuckRepaths` failure are unchanged; bots that stand still or loop within the radius are still caught.
