# Quest fix R6: loot task safety (sim run R6)

Change (`src/server/game/Bots/BotQuest.cpp`, commits a0c8502f9a and 293866039b), following `code-review-botquest-r5.md`:

| Item | Done | What |

## Reading

* Deaths per bot-minute fell 13% against R5 (28.6 to 24.8; 960 to 833) but remain well above R4 (13.7). The two R6 runs differ by 46 deaths, so a part of the difference is run noise; one run per variant cannot separate that. Deaths soon after a loot target (52 vs 44) did not fall even though the danger scan rejected 474 spawn visits, so the loot task is not the main source of the extra deaths over R4.
* Stuck events fell 7% (26.4 to 24.6 per 1000 bot-min), path failures 18% (11.9 to 9.8). Both still above R4. `UNREACHABLE_TARGET` stuck events went up slightly (100 to 111).
* Empty-spawn events almost doubled, but they now include per-bot skips that cost no walking (danger and path rejections at pick time); "not spawned" visits fell 957 to 927 while loot events rose 936 to 1117.
* `LOOT_EXHAUSTED` replaced part of `ITEM_NOT_DROPPING`; the quarantine count did not change (47 vs 45), so the loot exits were not the main feeder of it.
* The M4 check is a trade: 150 plus 50 "store failed" events, mostly 753 (98), 93552 (73), 3521 (31). The non-bag cases on 753 and 3521 were not investigated (possible unique or already-taken loot).
